# Практическая работа: контейнер для обучения модели

## Цель

Подготовить воспроизводимый Docker-образ, который обучает модель классификации,
сохраняет модель и метрики во внешнее хранилище, принимает параметры через
переменные окружения и запускается без прав `root`.

## Исходные данные

Используйте `sklearn.datasets.load_wine()` и
`RandomForestClassifier`. Код обучения должен находиться в отдельном файле
`train_model.py`.

Разделите данные через `train_test_split` со следующими параметрами:

- `test_size` берётся из переменной `TEST_SIZE`;
- `random_state` берётся из `RANDOM_STATE`;
- `stratify` получает целевой массив;
- количество деревьев берётся из `N_ESTIMATORS`.

Значения по умолчанию:

| Переменная | Значение |
|---|---:|
| `MODEL_DIR` | `/app/models` |
| `MODEL_VERSION` | `1.0.0` |
| `N_ESTIMATORS` | `150` |
| `TEST_SIZE` | `0.25` |
| `RANDOM_STATE` | `42` |

Некорректные значения должны завершать программу с понятной ошибкой до начала
обучения.

## Результаты обучения

После успешного запуска в `MODEL_DIR` должны находиться:

```text
wine_random_forest.joblib
metrics.json
```

`metrics.json` должен содержать:

```json
{
  "model_version": "1.0.0",
  "dataset": "wine",
  "accuracy": 0.95,
  "n_samples_train": 133,
  "n_samples_test": 45,
  "n_estimators": 150,
  "test_size": 0.25,
  "random_state": 42,
  "classes": ["class_0", "class_1", "class_2"],
  "created_at_utc": "2026-11-10T10:00:00+00:00"
}
```

Числа accuracy и размеров выборок в примере показывают форму файла. Сохраните
фактические результаты своего запуска.

Каталог с созданными моделями не добавляется в Git и build context.

## Требования к Dockerfile

Dockerfile должен:

- использовать официальный Python-образ с фиксированным major и minor тегом;
- сначала копировать `requirements.txt` и устанавливать зависимости;
- затем копировать код обучения;
- задавать абсолютный `WORKDIR`;
- устанавливать значения переменных окружения по умолчанию;
- создавать отдельного пользователя с фиксированными UID и GID;
- запускать обучение через exec form `CMD`;
- не содержать пароли, токены и локальные абсолютные пути;
- не обучать модель во время `docker build`.

Обучение должно происходить при `docker run`. Один запуск контейнера выполняет
одно обучение и завершается с кодом `0`.

## Постоянное хранение

Покажите два запуска:

1. с именованным volume;
2. с bind mount в локальный каталог `models`.

После удаления контейнера файлы модели и метрик должны оставаться доступными.
В README приведите команды создания хранилища, запуска контейнера и проверки
файлов.

## Параметризация

Выполните два запуска с разными значениями `N_ESTIMATORS` и `RANDOM_STATE`.
После каждого запуска сохраните `metrics.json` под отдельным именем или в
отдельном каталоге. В README сравните параметры и полученную accuracy.

## .dockerignore

Исключите как минимум:

- `.git`;
- виртуальные окружения;
- `__pycache__`;
- `.pytest_cache`;
- notebook;
- тесты;
- локальные модели и метрики.

## Автоматические тесты

Проверьте через `pytest`:

1. создание файла модели;
2. создание и структуру `metrics.json`;
3. загрузку модели через `joblib`;
4. предсказание для одного объекта;
5. отказ при `N_ESTIMATORS=0`;
6. отказ при `TEST_SIZE=0` и `TEST_SIZE=1`;
7. чтение параметров из переменных окружения.

Тесты выполняются локально и не должны обращаться к Docker Hub или внешней
сети.

## Проверка образа

В README сохраните команды и результаты следующих проверок:

```bash
docker build -t wine-trainer:1.0 .
docker image inspect wine-trainer:1.0
docker image history wine-trainer:1.0
docker run --rm --entrypoint id wine-trainer:1.0
```

Проверка `id` должна подтверждать, что основной процесс запускается не от
`root`.

## Работа не принимается

- модель обучается во время `docker build`;
- результаты остаются только внутри удаляемого контейнера;
- образ запускается только от `root` без обоснования;
- зависимости устанавливаются при каждом `docker run`;
- в образ попали `.git`, виртуальное окружение или готовые локальные модели;
- параметры запуска записаны в коде и не могут быть переопределены;
- единственным подтверждением работы является скриншот.
