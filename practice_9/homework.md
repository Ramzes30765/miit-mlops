# Практика 9. Инференс в Triton

Продолжайте работу в репозитории [практики 8](../practice_8/onnx_practice.md).
Используйте тот же ONNX-файл YOLO-детектора, `preprocess.py` и тестовые
изображения. Перед запуском проверьте SHA-256 детектора по отчёту практики 8.

В качестве основы возьмите [пример FastAPI](main.py), [постобработку](utils.py),
[Compose-файл](docker-compose.yaml) и [конфигурацию детектора](triton_model_repo/yolo_det/config.pbtxt).

## 1. Запуск в Docker

Соберите образ FastAPI и опишите запуск FastAPI и Triton в одном Compose-файле.
Подключите модельный репозиторий к Triton. Передайте адрес Triton в FastAPI
через переменную окружения. Внутри сети Compose используйте имя сервиса
Triton, например `triton:8000`. Опубликуйте порт FastAPI на хосте.

Проверьте, что после `docker compose up --build` модель `yolo_det` готова
к инференсу, а `POST /infer` принимает изображение и возвращает детекции.
На машине без GPU уберите обязательный NVIDIA runtime из Compose и используйте
CPU instance group.

## 2. Батчи и сравнение с ONNX Runtime

1. Настройте `max_batch_size` не меньше 2. Проверьте имена и типы тензоров
   в `config.pbtxt`. При включённом батчинге указывайте в `dims` размеры
   без оси батча. [Конфигурация модели Triton](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/user_guide/model_configuration.html#maximum-batch-size)
2. Добавьте `POST /infer_batch`. Принимайте несколько изображений и собирайте
   один тензор. Выполняйте один вызов Triton на весь батч. Возвращайте
   результаты в порядке входных изображений.
3. Сделайте проверку, которая отправляет один и тот же тензор в локальный
   ONNX Runtime и напрямую в Triton. Сравните сырой `output0` до NMS для
   батчей из одного и двух изображений. Проверьте формы и значения через
   `numpy.allclose` с `rtol=1e-3` и `atol=1e-3`. Запишите максимальное
   абсолютное расхождение.

Локальный скрипт и FastAPI должны использовать одну функцию подготовки
изображений из практики 8.

## 3. Детекция и NMS

Проверьте и доработайте `postprocess_yolo_det`. Для каждого изображения
отфильтруйте детекции по порогу уверенности, примените NMS отдельно по
классам и переведите координаты боксов в размеры исходного изображения.
Ограничьте координаты границами изображения.

Покажите результат на обоих тестовых изображениях. Проверьте на двух
перекрывающихся боксах одного класса, что NMS оставляет бокс с большей
уверенностью. Обработайте случай, когда порог не прошла ни одна детекция.

## 4. Сегментация

Добавьте в Triton модель `yolo_seg`. Возьмите веса `yolo11s-seg.pt` и
[экспортируйте их в ONNX](https://docs.ultralytics.com/modes/export/).
Используйте размер входа 640 на 640, FP32, динамическую ось батча и экспорт
без встроенного NMS. Выберите opset, который поддерживает версия ONNX Runtime
в используемом образе Triton. Зафиксируйте источник весов, версию экспортера,
команду экспорта и SHA-256 ONNX-файла в README.

Настройте конфигурацию по фактическим именам и формам тензоров. Реализуйте
постобработку масок. Отфильтруйте предсказания по уверенности, устраните
дублирующиеся детекции и приведите маски к размеру исходного изображения.
Через FastAPI возвращайте классы, уверенность и маски или контуры. Покажите
результат на тестовых изображениях.

## 5. Ансамбль Triton

Добавьте `yolo_ensemble`. Настройте `ensemble_scheduling` так, чтобы один
входной тензор использовали `yolo_det` и `yolo_seg`. Для каждого выхода
задайте отдельное имя. Ансамбль должен поддерживать батч из двух изображений.
[Ансамбли Triton](https://docs.nvidia.com/deeplearning/triton-inference-server/user-guide/docs/user_guide/ensemble_models.html)

Добавьте вызов ансамбля в FastAPI. Один запрос должен возвращать и детекции,
и результат сегментации. Сравните результат с отдельными вызовами двух
моделей для того же входа.

## 6. Нагрузочная проверка

Используйте `perf_analyzer` для измерения времени ответа и пропускной
способности. Отдельно укажите, какой порт и протокол вы использовали.
Во всех сравнениях используйте вход 640 на 640.

1. Измерьте `yolo_det`, `yolo_seg` и `yolo_ensemble` при одинаковых
   размере батча и числе параллельных запросов.
2. Для ансамбля сравните не менее двух размеров батча и двух уровней
   параллельности. Размер батча не должен превышать `max_batch_size`.
3. Запишите для каждого замера модель, размер батча, параллельность,
   p50 и p95 в миллисекундах, пропускную способность и ошибки.
4. По успешным замерам ансамбля выберите настройку с минимальным p95 и
   настройку с максимальной пропускной способностью при p95 до 1000 мс.
   Если на вашей машине этот порог не достигнут, покажите замеры и отдельно
   укажите результат при пороге 5000 мс.

По согласованию с преподавателем вместо детекции и сегментации можно
использовать ансамбль двух текстовых моделей. В таком случае согласуйте
модели до практики 8 и сохраните проверку одинакового входа в ONNX Runtime
и Triton, батчи и нагрузочные измерения.
