# Практика 8. Локальный инференс в ONNX Runtime

## Общий проект для практик 8 и 9

Создайте репозиторий `mlops-inference-<surname>`. В этой практике проверьте
YOLO-детектор локально и сохраните способ подготовки входа и проверки выхода.
В [практике 9](../practice_9/homework.md) запустите тот же ONNX-файл в Triton и
сравните результаты. Сдайте один репозиторий после обоих этапов.

## Исходные материалы

- [Ноутбук с примером экспорта ResNet50](onnx_runtime.ipynb).
- [YOLO11s в ONNX](../practice_9/triton_model_repo/yolo_det/1/model.onnx).
- [Тестовое изображение bus.jpg](../practice_9/bus.jpg).

Для самостоятельной работы используйте YOLO. Сохраните ONNX-файл без изменений
по пути `triton_model_repo/yolo_det/1/model.onnx` в своём проекте. Этот же
файл будет загружать Triton. Зафиксируйте в отчёте SHA-256 модели и изображения.

## 1. Проверка модели

1. Создайте окружение Python 3.12 и зафиксируйте зависимости для проверки
   ONNX, подготовки изображений и запуска ONNX Runtime. Если в практике 9
   используется Triton 24.09, возьмите ONNX Runtime 1.19.2 для локальной
   проверки. [Версии компонентов Triton 24.09](https://docs.nvidia.com/deeplearning/triton-inference-server/release-notes/rel-24-09.html)
2. Проверьте модель через `onnx.checker.check_model`. Запишите opset.
3. Загрузите модель через `InferenceSession` с `CPUExecutionProvider`.
   Выведите имена, типы и формы её входов и выходов.

В отчёте объясните, какая ось отвечает за размер батча. У детектора вход
`images` имеет форму `[B, 3, H, W]`, а выход `output0` имеет форму
`[B, 84, A]`. Здесь `A` обозначает число кандидатов на детекцию до NMS.
Запишите фактические размеры выхода при размере изображения 640 на 640.

## 2. Одиночный и батчевый инференс

1. Вынесите подготовку изображения в `preprocess.py`. Используйте RGB,
   изменение размера до 640 на 640, значения `float32` от 0 до 1 и порядок
   осей `C, H, W`.
2. В `run_onnx.py` выполните один вызов для `bus.jpg` и один вызов для
   батча из двух изображений. Вторым изображением может быть горизонтально
   отражённый `bus.jpg`. Сохраните порядок изображений в батче.
3. Проверьте, что выходы содержат конечные числа, а выход для каждого
   изображения из батча совпадает с его одиночным выходом с допустимой
   численной погрешностью. Используйте `numpy.allclose` с `rtol=1e-3` и
   `atol=1e-3`. Запишите максимальное абсолютное расхождение.

Сделайте проверку повторяемой по команде из README. На следующем этапе
используйте ту же функцию подготовки входа для сравнения с Triton.

## 3. Измерение времени

Для батчей из одного и двух изображений выполните по пять прогревочных
вызовов и не менее 20 измерений. Измеряйте только вызов модели на уже
подготовленном тензоре. В `REPORT.md` запишите устройство, версию ONNX
Runtime, размер батча, форму выхода, медиану и p95 времени вызова в
миллисекундах.
