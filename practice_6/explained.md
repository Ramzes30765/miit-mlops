# FastAPI для ML-сервисов

FastAPI используется как HTTP-слой между моделью и клиентом. Клиент отправляет
данные, сервис проверяет запрос, вызывает модель и возвращает результат в
заранее определённом формате.

Для устойчивого ML-сервиса нужны не только функция предсказания и адрес
`/predict`. Необходимо определить схему входа, схему ответа, коды состояния,
обработку ошибок, проверку готовности и способ тестирования API.

## Основные термины

| Термин | Значение |
|---|---|
| Приложение | Объект `FastAPI`, который хранит настройки и подключённые маршруты |
| Маршрут | Сочетание HTTP-метода и пути, например `GET /health` |
| Endpoint | Маршрут вместе с функцией, которая обрабатывает запрос |
| Обработчик | Python-функция, вызываемая для конкретного маршрута |
| JSON | Текстовый формат данных, который используется в теле запросов и ответов |
| Схема | Описание полей, типов и ограничений данных |
| Валидация | Проверка входных данных по схеме до выполнения обработчика |
| Инференс | Применение уже обученной модели к новым входным данным |
| Latency | Время от начала обработки запроса до получения результата |
| Health endpoint | Маршрут для проверки состояния и готовности сервиса |

## HTTP-запрос и ответ

HTTP-запрос содержит:

- метод;
- путь;
- параметры;
- заголовки;
- тело запроса, если оно предусмотрено методом и контрактом API.

Ответ содержит код состояния, заголовки и тело.

Основные методы:

| Метод | Назначение |
|---|---|
| `GET` | Получение ресурса или состояния |
| `POST` | Создание ресурса или запуск вычисления |
| `PUT` | Полная замена ресурса |
| `PATCH` | Частичное изменение ресурса |
| `DELETE` | Удаление ресурса |

Для инференса обычно используется `POST`, потому что входные данные передаются
в теле запроса.

## Коды состояния

| Код | Значение |
|---:|---|
| `200` | Запрос выполнен |
| `201` | Ресурс создан |
| `400` | Приложение отклонило запрос как некорректный |
| `404` | Ресурс не найден |
| `409` | Запрос конфликтует с текущим состоянием |
| `422` | Данные не прошли валидацию |
| `500` | Необработанная ошибка приложения |
| `503` | Сервис временно не готов выполнять запросы |

Код ответа является частью контракта. Если пользователь не найден, сервис
должен вернуть `404`, а не словарь с текстом ошибки под кодом `200`.

FastAPI обычно возвращает `422`, если JSON не соответствует Pydantic-схеме:
отсутствует обязательное поле, передан неверный тип или нарушено ограничение.
Код `400` используют для других ошибок клиента, которые приложение проверяет
самостоятельно.

## Минимальное приложение

```python
from fastapi import FastAPI

app = FastAPI(title="Example API", version="1.0.0")


@app.get("/")
def root():
    return {"message": "Hello World"}
```

Запуск из директории практики:

```bash
uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

`app.main` указывает на модуль `app/main.py`. Последнее `app` является объектом
`FastAPI` внутри модуля.

Для запуска другого файла меняется только путь к модулю:

```bash
uvicorn app.main_v2:app --reload --host 127.0.0.1 --port 8000
```

Эта команда импортирует объект `app` из `app/main_v2.py`. Одновременно на одном
порту может работать только один процесс сервера.

Флаг `--reload` подходит для разработки. В production он не используется.

## Path и query параметры

Path-параметр является частью адреса:

```python
@app.get("/items/{item_id}")
def get_item(item_id: int):
    return {"item_id": item_id}
```

Запрос `GET /items/12` передаст число `12` в `item_id`. Запрос
`GET /items/abc` вернёт `422`, потому что строку `abc` нельзя преобразовать в
`int`.

Query-параметры находятся после символа `?`:

```python
from fastapi import Query


@app.get("/search")
def search(
    query: str,
    limit: int = Query(default=10, ge=1, le=100),
):
    return {"query": query, "limit": limit}
```

Параметры `query` и `limit` отсутствуют в пути `/search`, поэтому FastAPI
считает их query-параметрами:

- `query: str` содержит текст для поиска. Значение по умолчанию не указано,
  поэтому параметр обязателен;
- `limit: int` содержит максимальное количество результатов;
- `default=10` используется, если клиент не передал `limit`;
- `ge=1` означает, что `limit` должен быть больше или равен `1`;
- `le=100` означает, что `limit` должен быть меньше или равен `100`.

Обычный HTTP-запрос:

```text
GET /search?query=model&limit=5
```

Здесь строка `model` попадёт в переменную `query`, а число `5` в переменную
`limit`.

Параметр `limit` можно не передавать:

```text
GET /search?query=model
```

В этом случае функция получит `limit=10`. Запрос
`GET /search?query=model&limit=0` вернёт `422`, потому что значение нарушает
ограничение `ge=1`. Запрос без `query` также вернёт `422`, потому что обязательный
параметр отсутствует.

Через `TestClient` тот же запрос записывается так:

```python
client.get(
    "/search",
    params={"query": "model", "limit": 5},
)
```

Словарь `params` преобразуется в строку `?query=model&limit=5`.

## Тело запроса и Pydantic

Pydantic-модель описывает структуру JSON:

```python
from pydantic import BaseModel, Field


class Measurement(BaseModel):
    temperature: float = Field(ge=-100, le=200)
    sensor_id: int = Field(ge=1)


@app.post("/measurements")
def create_measurement(measurement: Measurement):
    return measurement
```

`BaseModel` является базовым классом Pydantic. `Field` добавляет ограничения к
полю. Здесь `temperature` должна находиться от `-100` до `200`, а `sensor_id`
должен быть не меньше `1`. Оба поля обязательны, потому что для них не заданы
значения по умолчанию.

Если параметр обработчика имеет тип `Measurement`, FastAPI:

- читает JSON из тела запроса;
- проверяет типы и ограничения;
- создаёт объект модели;
- добавляет схему в OpenAPI.

JSON `{"temperature": 21.5, "sensor_id": 3}` будет преобразован в объект
`measurement`. Внутри функции значения доступны как `measurement.temperature`
и `measurement.sensor_id`.

Ошибка валидации возвращается с кодом `422`. Обработчик при этом не вызывается.

В `TestClient` JSON передаётся аргументом `json`:

```python
client.post(
    "/measurements",
    json={"temperature": 21.5, "sensor_id": 3},
)
```

Аргумент `params` используется для параметров в URL, а `json` для тела
запроса. Эти способы передачи данных не взаимозаменяемы.

## Входная и выходная схемы

Входная схема может содержать поля, которые нельзя возвращать клиенту. Пароль,
токен и внутренний идентификатор хранилища не должны случайно попадать в ответ.

`UserCreate` и `UserResponse` не являются встроенными классами FastAPI. Это
названия Pydantic-моделей, которые разработчик создаёт для своего API.

```python
class UserCreate(BaseModel):
    name: str
    password: str


class UserResponse(BaseModel):
    id: int
    name: str
```

Схема ответа задаётся через `response_model`:

```python
@router.post("", response_model=UserResponse, status_code=201)
def create_user(user: UserCreate):
    return {"id": 1, "name": user.name}
```

Если роутер создан с `prefix="/users"`, пустая строка в `@router.post("")`
означает маршрут `POST /users`. Дополнительная часть пути не добавляется.

Параметр `user: UserCreate` описывает тело входного запроса. В нём присутствует
пароль. В реальном сервисе пароль хэшируется и сохраняется, но не включается в
HTTP-ответ.

`response_model=UserResponse` задаёт схему ответа. Клиент получает только `id`
и `name`. FastAPI проверяет возвращённый словарь по `UserResponse` и преобразует
его в JSON. Код `201` сообщает, что ресурс создан.

В коде также можно использовать именованную константу:

```python
from fastapi import status

status_code=status.HTTP_201_CREATED
```

Она равна числу `201`, но по названию видно назначение кода.

Для нового списка используется `default_factory`:

```python
items: list[ItemResponse] = Field(default_factory=list)
```

Если поле `items` отсутствует, Pydantic создаёт отдельный пустой список для
каждого объекта. Запись `items=[]` в описании модели может привести к
нежелательному совместному использованию изменяемого значения в обычных
Python-классах, поэтому явная фабрика понятнее и безопаснее.

## EmailStr и дополнительные зависимости

Тип `EmailStr` выполняет проверку адреса электронной почты:

```python
from pydantic import BaseModel, EmailStr


class User(BaseModel):
    email: EmailStr
```

Для работы этого типа нужен пакет `email-validator`. Одного Pydantic
недостаточно. Зависимость должна быть указана в файле окружения.

## Ошибки через HTTPException

Ожидаемая ошибка API задаётся явно:

```python
from fastapi import HTTPException

users_by_id = {1: {"id": 1, "name": "Alice"}}


def find_user(user_id: int):
    user = users_by_id.get(user_id)
    if user is None:
        raise HTTPException(status_code=404, detail="User not found")
    return user
```

Возврат `{"error": "User not found"}` из обработчика с `response_model` не
заменяет `HTTPException`. Такой словарь может нарушить схему ответа и привести
к ошибке `500`.

## APIRouter

`APIRouter` группирует связанные маршруты:

```python
from fastapi import APIRouter

router = APIRouter(prefix="/users", tags=["Users"])


@router.get("/{user_id}")
def get_user(user_id: int):
    return {"id": user_id}
```

Роутер подключается к приложению:

```python
app.include_router(router, prefix="/api/v1")
```

Итоговый путь будет иметь вид `/api/v1/users/{user_id}`.

## Версионирование API

Версия API нужна, когда изменение контракта ломает существующих клиентов.

Пример:

```text
/api/v1/users
/api/v2/users
```

Номер версии должен совпадать в имени приложения, документации и URL. Маршрут
версии 3 не должен находиться под префиксом `/api/v2`.

Не каждое изменение требует новой версии. Исправление внутренней реализации,
которое не меняет контракт, можно выпустить в текущей версии.

## Документация OpenAPI

OpenAPI является машиночитаемым описанием маршрутов, параметров, тел запросов
и ответов. FastAPI формирует его из обработчиков, аннотаций типов и
Pydantic-схем:

```text
/docs
/openapi.json
```

`/openapi.json` возвращает описание в JSON. `/docs` открывает Swagger UI,
который отображает эту схему как страницу и позволяет отправить тестовый
запрос из браузера. Ручная проверка не заменяет автоматические тесты.

Документация строится отдельно для каждого объекта `FastAPI`. Если запущен
`app.main_v2:app`, страница `/docs` покажет только маршруты приложения `v2`.
Маршруты из `main_v1.py` или `main_v3.py` туда не попадут.

## Проверка состояния сервиса

Минимальный health endpoint:

```python
@app.get("/health")
def health():
    return {"status": "ok", "model_version": "1.0.0"}
```

Ответ `200` означает, что процесс принимает запросы. Для настоящего ML-сервиса
проверка готовности может дополнительно подтверждать, что модель загружена и
доступны обязательные ресурсы.

Health endpoint не должен запускать тяжёлый инференс при каждом обращении.

## Контракт инференса

Пример входной схемы для модели Iris:

```python
class PredictRequest(BaseModel):
    sepal_length: float = Field(gt=0)
    sepal_width: float = Field(gt=0)
    petal_length: float = Field(gt=0)
    petal_width: float = Field(gt=0)
```

Пример ответа:

```python
class PredictResponse(BaseModel):
    predicted_class: int
    class_name: str
    probabilities: list[float]
    model_version: str
    latency_ms: float = Field(ge=0)
```

Имена входных полей фиксируют смысл и порядок признаков. Порядок значений в
`probabilities` должен совпадать с порядком классов в метаданных модели.
Версия модели также является частью ответа. Клиент не должен угадывать эти
правила по реализации сервиса.

## Файлы и бинарные данные

Для изображения или другого файла используется `UploadFile`:

```python
from fastapi import File, UploadFile


@app.post("/image-info")
async def image_info(file: UploadFile = File(...)):
    content = await file.read()
    return {"filename": file.filename, "size": len(content)}
```

`File(...)` означает, что файл обязателен. Для обработки формы
`multipart/form-data` FastAPI нужен пакет `python-multipart`:

```bash
python -m pip install python-multipart
```

Нужно проверять тип содержимого, размер и возможность декодирования. Одного
расширения имени файла недостаточно.

## Синхронные и асинхронные обработчики

`async def` полезен, когда обработчик ожидает ввод-вывод: ответ другого
сервиса, чтение файла или операцию с базой данных. Во время ожидания Python
может обслуживать другие запросы. Обычное CPU-вычисление не становится быстрее
после добавления `async`.

Тяжёлый инференс занимает процессор или ускоритель и может блокировать обработку
следующих запросов. В рабочем сервисе применяют ограничение параллелизма,
очередь или отдельный процесс для инференса. Такой отдельный процесс часто
называют worker.

## TestClient

`TestClient` отправляет запросы приложению без запуска отдельного HTTP-сервера:

```python
from fastapi.testclient import TestClient

client = TestClient(app)


def test_health():
    response = client.get("/health")
    assert response.status_code == 200
    assert response.json()["status"] == "ok"
```

`client.get()` и `client.post()` возвращают объект ответа. Основные свойства:

- `response.status_code` содержит HTTP-код;
- `response.json()` преобразует JSON-ответ в словарь или список Python;
- `response.text` содержит исходный текст ответа.

Способ передачи данных зависит от контракта:

| Аргумент | Куда попадут данные | Пример |
|---|---|---|
| `params={"limit": 5}` | В URL после `?` | `/search?limit=5` |
| `json={"name": "Alice"}` | В JSON-тело запроса | `POST /users` |

Оператор `assert` сравнивает фактический результат с ожидаемым. Если условие
ложно, тест завершается ошибкой и показывает строку, на которой нарушен
контракт.

Нужно проверять не только успешный запрос. Минимальный набор включает:

- корректный запрос;
- ошибочный тип данных;
- нарушение ограничения Pydantic;
- отсутствующий ресурс;
- схему ответа;
- `/docs` и `/openapi.json`;
- отсутствие закрытых полей в ответе.

## Состояние в памяти

Списки и словари внутри Python-процесса подходят только для демонстрации.
Данные исчезнут после перезапуска и не будут согласованы между несколькими
workers. Каждый worker является отдельным процессом и имеет собственную копию
Python-списка.

Для production используют базу данных или другое внешнее хранилище. Тесты
должны очищать демонстрационное состояние между сценариями.

## Структура приложения

```text
app/
  main.py
  main_v1.py
  main_v2.py
  main_v3.py
  api/
    v1/
      users.py
      items.py
    v2/
      users.py
      items.py
    v3/
      llm.py
  models/
    schemas.py
tests/
  test_apps.py
```

`main.py` содержит начальный пример с базовыми маршрутами. Файлы `main_v1.py`,
`main_v2.py` и `main_v3.py` создают три отдельных приложения для следующих
этапов практики. Схемы данных находятся отдельно от обработчиков. Тесты не
входят в пакет приложения.

### Учебная версия 1

`main_v1.py` подключает `api/v1/users.py` и `api/v1/items.py` с префиксом
`/api/v1`. Роутер пользователей имеет собственный префикс `/users`.
Обработчик получения пользователя имеет суффикс `/{user_id}`. Итоговый путь:

```text
/api/v1 + /users + /{user_id} = /api/v1/users/{user_id}
```

В этой версии ответы составляются непосредственно в обработчиках. Схемы
запроса и ответа не используются. Задача `v1` состоит в том, чтобы показать
разделение маршрутов по файлам, работу `APIRouter` и сборку полного URL из
префиксов.

### Учебная версия 2

`main_v2.py` подключает новые роутеры из `api/v2` с префиксом `/api/v2`.
Создание пользователя обрабатывается по адресу `POST /api/v2/users`.

Модели `UserCreate`, `UserResponse`, `ItemCreate` и `ItemResponse` находятся в
`models/schemas.py`. Входная модель проверяет тело запроса. Выходная модель
фиксирует поля ответа. Поэтому пароль присутствует в `UserCreate`, но не
попадает в `UserResponse`.

Роутеры хранят созданные объекты в списках `fake_users_db` и `fake_items_db`.
Это временное хранилище для демонстрации. Оно очищается после перезапуска
процесса. Если пользователь не найден, обработчик явно возвращает `404` через
`HTTPException`.

При создании предмета `owner_id` должен совпадать с идентификатором созданного
пользователя. Если владельца нет, API возвращает `404` с сообщением
`Owner not found`. Созданный предмет сохраняется в общем списке предметов и в
поле `items` его владельца.

`v2` показывает валидацию, response model, коды ответа и обработку ожидаемых
ошибок.

### Учебная версия 3

`main_v3.py` подключает `api/v3/llm.py` с префиксом `/api/v3` и объявляет
маршрут `/health`. Роутер добавляет путь `/predict-text`. Полный адрес:

```text
/api/v3 + /predict-text = /api/v3/predict-text
```

Для запроса и ответа используются модели `TextPredictIn` и `TextPredictOut` из
`models/schemas.py`. Обработчик не вызывает настоящую модель. Он формирует
демонстрационный ответ из переданного текста и возвращает фиксированную версию
`demo-llm-v1`.

`v3` не включает маршруты пользователей и предметов из `v2`. Это отдельный
учебный пример API для ML-сервиса. Он показывает контракт inference endpoint,
проверку состояния через `/health`, версию модели и время обработки.

## Типовые ошибки

### Неверный рабочий каталог

Команда `uvicorn app.main:app` должна выполняться из директории, где доступен
пакет `app`.

### Зависимость не зафиксирована

Если код использует `EmailStr`, пакет `email-validator` должен находиться в
`requirements.txt` или `pyproject.toml`.

### Неправильный код ответа

Ожидаемая ошибка клиента не должна превращаться в `500`. Используйте
`HTTPException` и проверяйте код тестом.

### Разные версии в пути и коде

Префикс `/api/v3` должен соответствовать версии приложения и описанию API.

### Секреты в ответе

Пароль, токен и внутренние служебные поля не включаются в response model.

### Проверка только через Swagger UI

Ручной запрос не защищает от регрессии. Критические контракты закрепляются
автоматическими тестами.
