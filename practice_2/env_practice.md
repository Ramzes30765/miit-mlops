# Практическая работа: окружения и зависимости Python

## Цель

Научиться создавать изолированное окружение Python, фиксировать зависимости и
восстанавливать проект на чистом окружении двумя способами:

- с помощью `venv`, `pip` и `requirements.txt`;
- с помощью Poetry, `pyproject.toml` и `poetry.lock`.

Перед выполнением работы изучите [explained.md](explained.md). В нём находятся
объяснения терминов и справочные команды, но нет готовой последовательности
решения.

## Исходные материалы

В директории практики находится файл `plt_temp.py`. Скрипт:

- получает почасовую температуру Москвы через Open-Meteo;
- выбирает первые 24 значения;
- сохраняет их в `temperature_24h.csv`;
- строит график температуры.

Используйте этот скрипт как исходный код проекта. Не добавляйте директории
виртуальных окружений в Git.

## Общие требования

- Используйте Python 3.12.
- Окружение каждого этапа должно называться `.venv` и находиться внутри
  директории соответствующего проекта.
- Устанавливайте только библиотеки, которые действительно нужны исходному коду
  или инструментам разработки.
- Все команды должны выполняться из терминала, открытого в директории проекта.
- Результат должен воспроизводиться после удаления локального окружения.
- Не добавляйте в Git `.venv`, кэши Python и кэши инструментов разработки.
- Не используйте глобально установленные библиотеки для запуска проекта.

## Часть 1. venv, pip и requirements.txt

Создайте директорию `pip_project` и поместите в неё копию `plt_temp.py`.

### 1. Подготовка окружения

1. Создайте внутри `pip_project` виртуальное окружение `.venv` с Python 3.12.
2. Активируйте окружение.
3. Проверьте версию Python и путь к исполняемому файлу интерпретатора.
4. Сохраните результат проверки в отчёт.

Ожидаемый результат: путь к интерпретатору содержит `pip_project` и `.venv`, а
версия интерпретатора начинается с `3.12`.

### 2. Установка зависимостей

1. Определите сторонние библиотеки, которые импортирует `plt_temp.py`.
2. Установите их в созданное окружение.
3. Объясните в отчёте, почему модуль `numpy` не нужно добавлять как прямую
   зависимость этого скрипта, даже если он появился в списке установленных
   пакетов.
4. Запустите программу.

Ожидаемый результат:

- программа завершается без ошибки;
- создан файл `temperature_24h.csv`;
- CSV содержит столбцы `time` и `temperature_c`;
- в CSV находится 24 строки с данными, не считая заголовка;
- построен график температуры.

### 3. Фиксация и восстановление окружения

1. Создайте `requirements.txt` с точными версиями пакетов текущего окружения.
2. Деактивируйте и удалите только директорию `pip_project/.venv`.
3. Создайте новое пустое окружение с тем же именем.
4. Восстановите зависимости только из `requirements.txt`.
5. Повторно запустите скрипт и проверьте CSV.

Ожидаемый результат: программа повторно работает без ручной установки
отдельных библиотек.

## Часть 2. Poetry

Создайте отдельную директорию `poetry_project` и поместите в неё исходный
`plt_temp.py`. Не копируйте в неё `.venv` и `requirements.txt` из первой части.

### 4. Инициализация проекта

1. Инициализируйте Poetry-проект.
2. Укажите поддержку Python в диапазоне от 3.12 включительно до 3.13 не
   включительно.
3. Включите непакетный режим проекта.
4. Настройте создание окружения `.venv` внутри `poetry_project`. Настройка не
   должна менять поведение Poetry для остальных проектов пользователя.
5. Выберите установленный Python 3.12 и создайте окружение.
6. Проверьте путь к окружению и интерпретатору.

Ожидаемый результат: в проекте находятся `pyproject.toml`, `poetry.toml` и
`.venv`; Poetry использует Python 3.12 из локального окружения проекта.

### 5. Основные зависимости и группы

1. Добавьте библиотеки, необходимые `plt_temp.py`, как основные зависимости.
2. Создайте группу `test` и добавьте в неё `pytest`.
3. Создайте группу `dev` и добавьте в неё `ruff`.
4. Получите дерево зависимостей и определите для каждого основного пакета хотя
   бы одну транзитивную зависимость.
5. Убедитесь, что одна библиотека не записана одновременно в несколько групп.

Ожидаемый результат: основные зависимости, `test` и `dev` явно разделены в
`pyproject.toml`, а точные версии разрешены в `poetry.lock`.

### 6. Доработка программы

Измените `plt_temp.py`:

1. Ограничьте время ожидания HTTP-запроса.
2. Проверяйте успешность HTTP-ответа до чтения JSON.
3. Вынесите преобразование списков времени и температуры в отдельную функцию,
   которая возвращает `DataFrame`.
4. Сохраняйте график в файл `temperature_24h.png`.
5. Программа должна по-прежнему сохранять `temperature_24h.csv`.

Функция преобразования должна принимать данные через аргументы и не выполнять
сетевой запрос. Это позволит проверить её отдельно от внешнего API.

Ожидаемый результат: один запуск создаёт CSV и PNG, а ошибка HTTP не маскируется
под ошибку разбора JSON.

### 7. Автоматическая проверка

Создайте тест для функции преобразования данных. В тесте используйте небольшие
локальные списки времени и температуры, без обращения к сети.

Тест должен проверять:

- названия столбцов;
- количество строк;
- сортировку строк по времени;
- соответствие температуры указанному времени после сортировки.

Запустите тесты внутри окружения Poetry.

Ожидаемый результат: тесты проходят без доступа к Open-Meteo.

### 8. Работа с группами

Проверьте установку зависимостей в трёх вариантах:

1. Основная группа без инструментов разработки и тестирования.
2. Только группа `test`.
3. Полное окружение проекта.

Для каждого варианта запишите в отчёт:

- какие группы были выбраны;
- доступны ли `pytest` и `ruff`;
- можно ли запустить основной скрипт;
- почему получился именно такой результат.

После эксперимента восстановите полное окружение.

### 9. Lock-файл и обновление зависимости

1. Зафиксируйте исходное состояние `pyproject.toml` и `poetry.lock` в Git.
2. Проверьте наличие устаревших зависимостей.
3. Выберите одну прямую зависимость и задайте для неё диапазон, который
   разрешает совместимые обновления, но запрещает следующую мажорную версию.
4. Обновите только выбранную зависимость.
5. Сравните изменения `pyproject.toml` и `poetry.lock`.

В отчёте объясните:

- изменилось ли ограничение прямой зависимости;
- изменилась ли её установленная версия;
- какие транзитивные зависимости изменились;
- почему обновление не должно выходить за заданный диапазон.

Если более новой совместимой версии нет, это не является ошибкой. Зафиксируйте
этот результат и объясните его.

### 10. Экспорт и чистое восстановление

1. Экспортируйте зависимости Poetry-проекта в `requirements.txt`.
2. Удалите только `poetry_project/.venv`.
3. Восстановите окружение по `pyproject.toml` и `poetry.lock`.
4. Запустите тесты.
5. Запустите основной скрипт.

Ожидаемый результат:

- окружение восстанавливается без ручного добавления пакетов;
- тесты проходят;
- скрипт создаёт `temperature_24h.csv` и `temperature_24h.png`;
- в CSV находится 24 строки данных.

## Отчёт

Создайте в корне выполненной работы файл `REPORT.md`. Добавьте в него:

1. Версию Python, версию Poetry и используемую операционную систему.
2. Пути к интерпретаторам обеих частей.
3. Список прямых зависимостей и их назначение.
4. По одному примеру транзитивной зависимости для каждого основного пакета.
5. Результат восстановления окружения `pip_project`.
6. Результат проверки групп Poetry.
7. Объяснение изменений после точечного обновления зависимости.
8. Результат чистого восстановления Poetry-проекта.
9. Краткое сравнение подходов `venv + pip` и Poetry: что именно обеспечивает
   воспроизводимость в каждом случае.

Не вставляйте в отчёт всю историю терминала. Приведите только команды проверки
и относящиеся к ним результаты.

## Критерии проверки

Работа считается выполненной, если:

- оба окружения изолированы и используют Python 3.12;
- зависимости первой части восстанавливаются из `requirements.txt`;
- Poetry-проект содержит осмысленное разделение основных, тестовых и
  разработческих зависимостей;
- `pyproject.toml` и `poetry.lock` согласованы;
- тест не обращается к сети и проверяет преобразование данных;
- после чистого восстановления тесты и программа запускаются;
- `.venv` и кэши не попали в Git;
- отчёт объясняет наблюдаемый результат, а не только перечисляет выполненные
  действия.
