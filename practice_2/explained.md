# Виртуальные окружения и зависимости Python

Python-проект обычно зависит не только от исходного кода, но и от конкретных
версий Python и сторонних библиотек. Если устанавливать все библиотеки в одно
системное окружение, требования разных проектов начинают конфликтовать.

Виртуальное окружение создаёт отдельную директорию с интерпретатором Python и
установленными пакетами. Изменения внутри этого окружения не затрагивают другие
проекты.

Этот файл является справочником. Он объясняет основные понятия и команды, но
не содержит пошагового решения практической работы.

## Что входит в окружение проекта

Для воспроизводимого Python-проекта важно зафиксировать несколько вещей:

- поддерживаемую версию Python;
- прямые зависимости проекта;
- допустимые версии прямых зависимостей;
- точные версии всех установленных зависимостей;
- способ создания окружения и запуска программы.

Прямая зависимость импортируется или используется самим проектом. Транзитивная
зависимость нужна одной из прямых зависимостей. Например, проект может напрямую
использовать `pandas`, а `pandas` установит дополнительные библиотеки,
необходимые для своей работы.

## Модуль venv

Модуль `venv` входит в стандартную библиотеку Python. Он создаёт виртуальное
окружение, но не управляет описанием проекта и lock-файлом.

### Создание окружения

Windows с Python Launcher:

```powershell
py -3.12 -m venv .venv
```

Linux:

```bash
python3.12 -m venv .venv
```

Имя `.venv` не является обязательным, но часто используется для окружения
внутри проекта. Директорию окружения не добавляют в Git.

### Активация и деактивация

PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

Bash или Zsh:

```bash
source .venv/bin/activate
```

Выход из активного окружения:

```bash
deactivate
```

После активации команды `python` и `pip` должны относиться к выбранному
окружению. Это можно проверить так:

```bash
python --version
python -c "import sys; print(sys.executable)"
```

Путь к интерпретатору должен указывать на директорию `.venv` текущего проекта.

## pip и requirements.txt

`pip` устанавливает Python-пакеты в текущее окружение. Надёжнее вызывать его
через тот интерпретатор, в который должны попасть пакеты:

```bash
python -m pip install requests
python -m pip install "numpy==1.26.4"
```

Просмотр установленных пакетов:

```bash
python -m pip list
python -m pip show numpy
python -m pip list --outdated
```

Фиксация точных версий установленных пакетов:

```bash
python -m pip freeze > requirements.txt
```

Установка пакетов из файла:

```bash
python -m pip install -r requirements.txt
```

`requirements.txt`, созданный через `pip freeze`, описывает состояние
окружения. В нём обычно находятся и прямые, и транзитивные зависимости. Сам по
себе этот файл не объясняет, какие пакеты были выбраны разработчиком напрямую.

Проверка воспроизводимости состоит не только в создании файла. Нужно убедиться,
что новое пустое окружение действительно можно восстановить из него и что
программа после этого запускается.

## Ограничения версий

Ограничение версии определяет множество допустимых выпусков пакета.

| Запись | Допустимые версии |
|---|---|
| `==1.2.3` | только `1.2.3` |
| `>=1.2.3,<2.0.0` | от `1.2.3` включительно до `2.0.0` не включительно |
| `^1.2.3` | `>=1.2.3,<2.0.0` |
| `^0.2.3` | `>=0.2.3,<0.3.0` |
| `^0.0.3` | `>=0.0.3,<0.0.4` |
| `~1.2.3` | `>=1.2.3,<1.3.0` |
| `1.2.*` | `>=1.2.0,<1.3.0` |
| `*` | любая версия |

Чем шире диапазон, тем больше новых версий сможет выбрать менеджер
зависимостей. Чем уже диапазон, тем предсказуемее установка, но тем чаще
ограничение придётся обновлять вручную.

В современном `pyproject.toml` зависимости обычно записываются в формате
PEP 621 как явные диапазоны. При добавлении зависимости Poetry может принять
короткую запись с `^` или `~` и преобразовать её в эквивалентный диапазон.

## Что делает Poetry

Poetry объединяет несколько задач:

- создаёт и выбирает виртуальное окружение;
- хранит описание проекта в `pyproject.toml`;
- разрешает совместимые версии зависимостей;
- записывает точное решение в `poetry.lock`;
- устанавливает зависимости и запускает команды внутри окружения.

Проверка установленной версии Poetry:

```bash
poetry --version
```

Инициализация проекта в существующей директории:

```bash
poetry init
```

Если виртуальное окружение должно находиться в `.venv` внутри проекта, настройку
лучше сделать локальной для проекта:

```bash
poetry config virtualenvs.in-project true --local
```

Локальная настройка сохраняется в `poetry.toml`. Она не меняет поведение Poetry
для остальных проектов. Если окружение проекта уже было создано в общем кэше,
одного изменения настройки недостаточно: новое расположение будет использовано
при следующем создании окружения.

## Выбор версии Python

```bash
poetry env use 3.12
```

Эта команда выбирает уже установленный интерпретатор. Она не скачивает и не
устанавливает Python. Если подходящего интерпретатора нет в системе, сначала
нужно установить его отдельным инструментом.

Информация о выбранном окружении:

```bash
poetry env info
poetry env info --path
poetry env info --executable
poetry env list --full-path
```

## Добавление и удаление зависимостей

Добавление основных зависимостей программы:

```bash
poetry add requests pandas matplotlib
```

Добавление зависимости с ограничением версии:

```bash
poetry add "numpy@>=1.26,<2.0"
```

Удаление зависимости:

```bash
poetry remove numpy
```

Просмотр зависимостей:

```bash
poetry show
poetry show pandas
poetry show --tree
poetry show --outdated
```

Обновление одной зависимости выполняется отдельно от обновления всего проекта:

```bash
poetry update pandas
```

Обновление происходит только в пределах ограничения, записанного в
`pyproject.toml`.

## Группы зависимостей

Библиотеки, необходимые самой программе во время работы, относятся к основной
группе. Инструменты разработки и тестирования лучше хранить отдельно.

```bash
poetry add --group dev ruff
poetry add --group test pytest coverage
```

Группа, созданная таким способом, по умолчанию не является опциональной и
устанавливается обычной командой `poetry install`. Опциональность задаётся в
`pyproject.toml`, если группу требуется подключать только по запросу.

Примеры выбора групп при установке:

```bash
poetry install --without dev
poetry install --only main
poetry install --only test
poetry install --with docs
```

Параметр `--with` нужен для опциональной группы. Основная группа называется
`main`.

## pyproject.toml и poetry.lock

`pyproject.toml` описывает намерения разработчика:

- имя и версию проекта;
- поддерживаемые версии Python;
- прямые зависимости и допустимые диапазоны;
- группы зависимостей;
- настройки сборки и инструментов.

`poetry.lock` хранит конкретное согласованное решение: точные версии прямых и
транзитивных зависимостей, сведения о файлах пакетов и маркеры окружения.

Основные операции:

```bash
poetry lock
poetry install
poetry update
poetry sync
```

- `poetry lock` пересчитывает lock-файл без установки пакетов;
- `poetry install` устанавливает зависимости согласно lock-файлу;
- `poetry update` ищет более новые допустимые версии и обновляет lock-файл;
- `poetry sync` дополнительно удаляет из окружения пакеты, отсутствующие в
  выбранном наборе зависимостей.

Полное построение lock-файла заново:

```bash
poetry lock --regenerate
```

Эту операцию не следует использовать вместо обычного точечного обновления без
понимания причины: она может изменить сразу много транзитивных зависимостей.

## Проект без собственного Python-пакета

Если репозиторий содержит только скрипты и не должен устанавливаться как
отдельный Python-пакет, в `pyproject.toml` можно использовать непакетный режим:

```toml
[tool.poetry]
package-mode = false
```

Другой вариант - не устанавливать корневой пакет при конкретном запуске:

```bash
poetry install --no-root
```

Если проект должен импортироваться как пакет, часто применяется структура
`src`:

```text
project_root/
  pyproject.toml
  src/
    weather_app/
      __init__.py
      main.py
```

Для обычного учебного скрипта создавать пакет необязательно.

## Запуск команд в окружении Poetry

Запуск Python-файла:

```bash
poetry run python path/to/script.py
```

Запуск тестов и других установленных инструментов:

```bash
poetry run pytest
poetry run ruff check .
```

`poetry run` выполняет следующую за ним команду внутри окружения проекта.
Само имя файла `.py` не является командой, если для него отдельно не создана
консольная точка входа.

## Экспорт requirements.txt

Экспорт выполняет плагин `poetry-plugin-export`. Способ установки плагина
зависит от того, как был установлен сам Poetry, а не от операционной системы.
Перед установкой можно проверить доступные плагины:

```bash
poetry self show plugins
```

Один из способов установки, если он подходит для текущей установки Poetry:

```bash
poetry self add poetry-plugin-export
```

После установки плагина:

```bash
poetry export --format requirements.txt --output requirements.txt
```

Экспортированный файл удобен для систем, которые устанавливают зависимости
только через `pip`. Основными файлами Poetry-проекта при этом остаются
`pyproject.toml` и `poetry.lock`.

## Конфликты зависимостей

Конфликт возникает, когда невозможно подобрать версии, одновременно
удовлетворяющие всем ограничениям. Сообщение resolver обычно показывает, какие
два или несколько требований несовместимы.

Перед изменением `requires-python` или диапазона библиотеки нужно выяснить:

1. Какая зависимость предъявляет несовместимое требование.
2. Какие версии Python и библиотеки действительно нужны проекту.
3. Можно ли обновить или понизить конкретную зависимость.
4. Не скрывает ли широкое ограничение реальную несовместимость.

Не следует произвольно менять поддерживаемую версию Python только для того,
чтобы resolver перестал выводить ошибку.

## Что не добавляют в Git

Обычно в `.gitignore` добавляют:

```gitignore
.venv/
__pycache__/
*.py[cod]
.pytest_cache/
.ruff_cache/
```

В Git, напротив, сохраняют `pyproject.toml`, `poetry.lock`, исходный код,
тесты и необходимые инструкции по запуску. Lock-файл нужен для повторяемой
установки и должен изменяться вместе с зависимостями проекта.

## Краткое сравнение

| Возможность | venv и pip | Poetry |
|---|---|---|
| Изоляция окружения | `venv` | встроено |
| Установка пакетов | `pip` | встроено |
| Описание прямых зависимостей | вручную | `pyproject.toml` |
| Разрешение совместимых версий | при установке | отдельный resolver |
| Lock-файл | нет | `poetry.lock` |
| Группы зависимостей | нет встроенной модели | есть |
| Запуск внутри окружения | после активации | `poetry run` |

Независимо от инструмента воспроизводимость подтверждается только проверкой в
новом пустом окружении.
