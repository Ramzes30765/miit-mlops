# Практическая работа по Git

После завершения каждого пункта, предполагается, что вы пушите все изменения в удалённый репозиторий.

1. Создайте новый репозиторий с названием по шаблону:

    `mlops-git-<your_surname>`

    Клонируйте удалённый репозиторий в локальный.

    Основная ветка репозитория должна называться `main`. Если Git создал основную ветку с другим именем, переименуйте её перед первой отправкой изменений.

2. Создайте файл `app.py` с содержимым `print("Start app")` и сделайте первый коммит

3. Создайте ветку `feature/train` (от `main`)

4. Создайте ветку `feature/metrics` (от `main`)

    Добавьте файл `metrics.py` с содержимым `print("Compute my metric")`

    Добавьте в файл `app.py` строку `print("Print metric")`

    Сделайте один коммит, содержащий изменения `metrics.py` и `app.py`.

5. Выполните слияние `feature/metrics` в `main`

6. В ветке `feature/train` добавьте файл `train.py` с содержимым `print("Model training")`

    Сделайте 3 коммита:

    * Создайте файл `train.py` с содержимым `print("Model training")`
    * Измените `app.py` так:

            print("Start app")
            print("Train my model")
            print("Print metric")

    * Измените `app.py` так:

            print("Start app")
            print("Train my model")
            print("Some bug")
            print("Print metric")

7. Выполните слияние `feature/train` в `main` без бага в `app.py`, но чтобы баг был виден в истории Git.

8. В `main` добавьте в конец `app.py` строку `print("Metrics branch commit")`. Не делайте коммит. Перенесите изменения в `feature/metrics` и закомитьте.

    Если при переносе возник конфликт, разрешите его, сохранив добавляемую строку, и завершите операцию.

9. В `feature/metrics` добавьте в конец `app.py` строку `print("Train branch commit")`. Сделайте коммит. Перенесите созданный коммит в `feature/train`.

    Если при переносе возник конфликт, разрешите его, сохранив добавляемую строку, и завершите операцию.

10. В `feature/metrics` в конец файла `metrics.py` добавьте отдельными коммитами:

    * `print("Good commit_1")`
    * `print("Bad commit_1")`
    * `print("Bad commit_2")`

    * ....
    * `print("Bad commit_N")` - N=3-5

    Откатите плохие коммиты, сохранив `Good commit_1`, таким образом, чтобы плохие коммиты не засоряли историю Git.

    P.S. Представьте, что N - очень большое число и ручное исправление займёт очень много времени.

11. Создайте ветку `feature/config` от `main`.

    Последовательно сделайте отдельные коммиты со следующими изменениями:

    * Создайте файл `config.py` со строкой `BATCH_SIZE = 16`
    * Добавьте строку `LEARNING_RATE = 0.01`
    * Добавьте строку `MODEL_NMAE = "baseline"`
    * Исправьте опечатку `MODEL_NMAE` на `MODEL_NAME`
    * Добавьте строку `DEBUG = True`
    * Удалите строку `DEBUG = True`

    Приведите историю ветки в порядок. В итоговой истории должно остаться только два логически законченных коммита:

    * Первый коммит создаёт конфигурацию обучения с параметрами `BATCH_SIZE` и `LEARNING_RATE`
    * Второй коммит добавляет параметр `MODEL_NAME`

    В итоговой версии `config.py` должны находиться строки:

        BATCH_SIZE = 16
        LEARNING_RATE = 0.01
        MODEL_NAME = "baseline"

    Коммиты с опечаткой и временной отладочной настройкой не должны остаться в истории. Удалять ветку и создавать файл заново нельзя.

12. Создайте ветку `feature/validation` от `main`.

    Создайте файл `validation.py` с содержимым:

        print("Validate model")

    Сделайте коммит с этим файлом. В рамках данного пункта не отправляйте ветку `feature/validation` в удалённый репозиторий.

    Перейдите в `main` и удалите локальную ветку `feature/validation` вместе с находящимся в ней коммитом.

    После удаления восстановите потерянный коммит средствами Git и создайте на его основе ветку `feature/validation-restored`.

    Требования к результату:

    * Ветка `feature/validation-restored` содержит исходный файл `validation.py`
    * Восстановленный коммит имеет тот же идентификатор, что и до удаления ветки
    * Повторно создавать `validation.py` или копировать в него содержимое вручную нельзя
    * После восстановления отправьте ветку `feature/validation-restored` в удалённый репозиторий

13. Смоделируйте совместную работу двух разработчиков с одним удалённым репозиторием.

    В ветке `main` создайте файл `README.md` со строкой:

        Project status: draft

    Сделайте коммит и отправьте его в удалённый репозиторий. После этого склонируйте репозиторий во вторую папку. Первая папка будет рабочей копией первого разработчика, вторая папка - рабочей копией второго разработчика.

    В первой рабочей копии:

    * Измените строку в `README.md` на `Project status: ready for training`
    * Сделайте коммит
    * Отправьте коммит в `main` удалённого репозитория

    Во второй рабочей копии, не получая предварительно изменения первого разработчика:

    * Измените ту же строку в `README.md` на `Project status: ready for inference`
    * Сделайте коммит
    * Попробуйте отправить коммит в `main`

    Отправка из второй рабочей копии должна быть отклонена, потому что удалённая ветка уже содержит неизвестный ей коммит.

    Получите изменения из удалённого репозитория во вторую рабочую копию и разрешите возникший конфликт, сохранив изменения обоих разработчиков. Итоговый `README.md` должен содержать две строки:

        Project status: ready for training
        Project status: ready for inference

    Отправьте разрешённый конфликт в удалённый репозиторий. Затем обновите `main` в первой рабочей копии и убедитесь, что обе копии содержат одинаковый `README.md` и одинаковую историю ветки `main`.

    Использовать принудительную отправку изменений в этом пункте запрещено.

14. В ветке `main` добавьте в конец `app.py` временную отладочную строку:

        print("Temporary debug")

    Сделайте коммит и отправьте его в удалённый репозиторий. Представьте, что этот коммит уже получили другие разработчики, поэтому переписывать опубликованную историю нельзя.

    Отмените изменение новым коммитом и отправьте результат в удалённый репозиторий.

    Требования к результату:

    * В текущей версии `app.py` отсутствует строка `print("Temporary debug")`
    * Коммит, добавивший временную строку, остаётся в истории
    * В истории присутствует отдельный коммит, отменяющий это изменение
    * Идентификаторы опубликованных коммитов не изменились
    * Принудительная отправка изменений не использовалась
